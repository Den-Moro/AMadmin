# Инструкция для администратора

Руководство по эксплуатации AMadmin: как поднять сервер, пользоваться админ-панелью и
раскатать клиент на кассы. Полное техническое ТЗ и архитектурные решения — в
[AGENTS.md](AGENTS.md); текущий статус разработки — в [README.md](README.md). Инструкция
для сотрудников магазина — в [INSTRUCTIONS.md](INSTRUCTIONS.md).

## 1. Что это за система

Два больших модуля:

1. **Оповещения** — сервер рассылает уведомления о плановых/срочных IT-работах на ПК
   магазинов; UI-агент на кассе показывает их поверх всех окон и подтверждает получение.
2. **Удалённое администрирование** — из панели можно на любом наборе касс: управлять
   службами Windows, завершать процессы, выполнять скрипты и программы, раскладывать
   файлы (со сравнением по хешу). Выполняет агент управления — служба Windows.

На каждой кассе работают два процесса: `AMadmin.UiAgent.exe` (в сессии кассира, показывает
окна) и `AMadmin.ManagementAgent.exe` (служба от SYSTEM, без окон, выполняет команды).
Это не прихоть: служба от SYSTEM не может показывать окна в сессии пользователя
(Session 0 isolation), а окно кассира не имеет прав управлять службами. Ключ (`agent_token`)
и конфиг у них общие — один файл `config.json` на ПК.

## 2. Требования к развёртыванию

### 2.1 Сервер

**Вариант A — Docker (для демонстрации и тестов):**
- Docker Desktop (Windows/Mac) или Docker Engine (Linux) — и больше ничего. PHP 8.3 с
  нужными расширениями и лимитами уже внутри образа.

**Вариант B — без Docker (реальный прод на Windows-хосте):**
- PHP 8.x с расширениями `pdo_sqlite` (база) и `zip` (выгрузка конфигов архивом). На
  Windows оба идут в комплекте с PHP — достаточно раскомментировать `extension=pdo_sqlite`
  и `extension=zip` в `php.ini`. Отдельную СУБД ставить не нужно: SQLite — это файл
  `server/data/amadmin.sqlite`.
- В `php.ini` поднять лимиты загрузки, иначе файлы для раскатки крупнее 2 МБ не
  загрузятся: `upload_max_filesize = 512M`, `post_max_size = 520M`.
- Веб-сервер: Apache с `mod_rewrite` или IIS (встроенный `php -S` — только для теста).
  Все запросы, не совпадающие с реальным файлом в `server/public/`, должны уходить в
  `public/index.php`.
- Старый Windows Server (вплоть до 2008): может понадобиться включить TLS 1.2 на уровне ОС.

**В обоих случаях:** сервер должен быть доступен по сети со всех касс (HTTP/HTTPS, в том
числе через корпоративный прокси) — входящих подключений к самим кассам не требуется,
вся архитектура на исходящем опросе. Папка `server/data/` (база + загруженные файлы)
и `server/logs/` должны быть доступны на запись.

### 2.2 Клиент (кассы/ПК администратора)

- **Windows 7 или новее** (жёсткое ограничение снизу).
- **.NET Framework 4.8.** На Windows 10 (с 2019 г.) и 11 уже установлен. На Windows 7 —
  через Windows Update или отдельным установщиком Microsoft (ndp48-x86-x64-allos). Это
  единственный .NET, который работает на Windows 7; современный .NET 6/7/8 — нет.
- **Сетевой доступ** до сервера. Прокси: если пусто в конфиге — берутся системные
  настройки Windows; можно указать свой (`proxy_url`, логин/пароль).
- **Права:** UI-агент — обычный пользователь (не администратор, не SYSTEM). Агент
  управления — служба, ставится из консоли администратора один раз.
- **Ключ этого ПК** (`agent_token`) — выдаётся панелью при заведении ПК (см. 4.1). Руками
  в базе ничего заводить не нужно.

## 3. Сервер

### 3.1 Запуск через Docker

```bash
docker compose up -d --build
```

Миграции (`server/migrations/`) накатываются автоматически при каждом старте контейнера
(`bin/migrate.php`, идемпотентно). Сервер слушает `http://localhost:8000`. База и
загруженные файлы живут на docker-томе `amadmin_data` и переживают пересборку образа.

Тестовые данные и первый логин:

```bash
docker compose exec server php -r "(new PDO('sqlite:/app/data/amadmin.sqlite'))->exec(file_get_contents('/app/dev-seed.sql'));"
docker compose exec server php bin/create-admin.php <логин> <пароль> [роль]
```

### 3.2 Запуск напрямую (без Docker)

См. «Без Docker» в [README.md](README.md). Продакшен по плану — ручная установка на
Windows-хосте (IIS/Apache); Docker — только для тестирования.

### 3.3 Роли администраторов

Задаются при создании (`create-admin.php <логин> <пароль> <роль>`), по умолчанию
`administrator`:

| Роль | Что может |
|---|---|
| `operator` | смотреть всё, отправлять оповещения, вести группы и мануалы |
| `administrator` | + отправлять команды на кассы, загружать файлы, менять настройки, заводить ПК |
| `superadmin` | то же, что administrator (зарезервировано под управление учётками) |

Проверка прав — на сервере; панель лишь показывает роль рядом с именем. После 5
неудачных попыток входа подряд логин временно блокируется.

### 3.4 Логи и диагностика

- Серверный лог: `server/logs/app.log` (в Docker — `docker compose exec server tail -f logs/app.log`).
  Каждая команда, кто и куда её отправил, каждый файл — там же, отключить нельзя.
- Уровень логирования — `log_level` в `config.php` (`debug`/`info`/`warning`/`error`).
  Пока бета — держите `debug`.
- Клиентские логи — рядом с `.exe`: `ui-agent.log` и `management-agent.log`, уровень
  через `log_level` в `config.json`.
- Если касса «не видит» оповещение: сначала `management-agent.log`/`ui-agent.log` на
  кассе (доходит ли опрос до сервера), потом `app.log` на сервере (что сервер ей отдал).

## 4. Админ-панель

Откройте `http://<адрес-сервера>/admin/login.html`. Над каждым полем в панели есть
короткая подсказка — здесь только то, что в подсказку не влезает.

### 4.1 Дашборд — ПК

- **Новый ПК** — магазин, тип, hostname; панель сразу выдаёт готовый `config.json` с
  ключом. Скопируйте и положите рядом с агентами на кассе.
- **Сразу много ПК** — список hostname (по одному в строке или через запятую) на весь
  магазин; уже заведённые пропускаются, а не ломают всю пачку.
- **Выгрузить конфиги архивом** — ZIP с папкой на каждую кассу из текущего списка
  (с учётом фильтров) и `config.json` внутри. Адрес сервера в конфигах — тот, по которому
  открыта панель. **Внутри ключи доступа**: храните архив как пароли, раскладывайте по
  кассам своими средствами (SMB/скрипт), не пересылайте открытыми каналами.
- Список ПК: онлайн/офлайн по времени последнего опроса, версия агента, «Показать конфиг»
  для любого ПК (например, при переустановке).

### 4.2 Оповещения

Текст, важность (важное — всегда принудительное окно, неважное — по настройке), размер,
кому (всем / магазину / группе / типу устройства / ПК), мануал из библиотеки или вручную.
Ниже — история со счётчиками показов/подтверждений. Как окно ведёт себя на кассе —
задаётся в Настройках.

### 4.3 Группы хостов

Произвольные группы ПК поверх структуры «магазин» (например «Кассы 1 этажа»). Группа —
цель и для оповещений, и для команд.

### 4.4 Мануалы

Инструкции для повторного использования в оповещениях. Текст копируется в оповещение
в момент отправки, поздняя правка мануала уже отправленное не меняет.

### 4.5 Команды (удалённое администрирование)

Выполняет агент управления при следующем опросе (обычно в пределах минуты). Результат
с каждой кассы — в таблице «Последние команды» → «Результаты». Перед отправкой панель
спрашивает «точно на N хостов?».

| Тип | Что делает | На что обратить внимание |
|---|---|---|
| **Служба** | запустить / остановить / перезапустить / список всех служб | системное имя, как в `services.msc`; защищённые службы отклоняются на сервере |
| **Процесс** | завершить по имени (все экземпляры) или PID / список | по PID — только на один конкретный ПК; защищённые процессы отклоняются |
| **Скрипт / программа** | PowerShell или CMD: текст скрипта, либо путь к файлу на кассе + аргументы | выполняется от SYSTEM; вывод и код возврата возвращаются; по таймауту процесс убивается вместе с потомками |
| **Файл** | разложить загруженный на сервер файл по указанному пути | касса сравнивает SHA-256 и качает только если файл отличается; старый файл остаётся рядом как `.bak.<дата>` |

**Файлы для раскатки** — раздел на той же странице: загрузить один раз, потом
использовать в любом числе команд. Удаляйте файл только когда команды с ним уже
выполнены. Скачать файл может только касса, которой адресована команда с этим файлом.

**Защита от массовой ошибки** — списки защищённых служб и процессов в Настройках.
Заранее добавьте туда процесс кассовой программы («Профи-Т»): одна ошибка иначе
положит кассы во всех магазинах разом. Внутри самого агента есть ещё неизменяемый
минимум (explorer, csrss, winlogon, lsass и т.п. и оба агента AMadmin).

Команды живут ограниченное время (Настройки → «Срок жизни команды», по умолчанию 24 ч):
касса, которая была выключена дольше, старые команды уже не получит — иначе после
месяца простоя на неё обрушились бы все рестарты и скрипты за этот месяц.

Что означают статусы: `success` — выполнено; `failed` — не выполнено, причина в
«Результате»; `timeout` — скрипт/служба не уложились в отведённое время; `in_progress`
— касса взяла команду, но ещё не отчиталась. Если касса перезапустилась посреди
выполнения, команда завершится `failed` с пометкой «повторно не запускалось» — агент
никогда не выполняет одну команду дважды.

### 4.6 Настройки

Всё поведение касс — из панели, без пересборки агента: принудительный режим, время до
разблокировки кнопки, подтверждение закрытия в два шага и защита от случайного касания
(сенсорные кассы), тихие часы (в часовом поясе магазина), звук, брендинг в окне,
защищённые службы/процессы, таймаут скриптов. Кассы подхватывают при следующем опросе.

## 5. Клиенты

### 5.1 Сборка

Нужен .NET SDK 8 на машине сборки (на кассах — только .NET Framework 4.8):

```bash
cd client
dotnet build Modules/Notifications/AMadmin.UiAgent.csproj -c Release
dotnet build Modules/Management/AMadmin.ManagementAgent.csproj -c Release
```

Результат — `bin/Release/net48/` в каждом модуле. На кассу нужны оба `.exe` с их `.dll`
рядом и один `config.json`.

### 5.2 Установка на кассу

1. Создайте папку, например `C:\AMadmin\`, скопируйте туда содержимое обеих папок сборки.
2. Положите рядом `config.json` этого ПК (из панели или из архива).
3. Агент управления — из консоли **от имени администратора**:
   ```
   C:\AMadmin\AMadmin.ManagementAgent.exe --install
   ```
   Появится служба `AMadminAgent` (автозапуск, автоперезапуск при сбое). Снять —
   `--uninstall`. Для отладки без установки — `--console` (тот же цикл в окне консоли).
4. UI-агент — в автозагрузку сессии кассира: задача планировщика «при входе пользователя»
   или ярлык в папке «Автозагрузка». **Не** от администратора и не от SYSTEM.
5. Через минуту ПК на дашборде станет «онлайн», версия агента заполнится.

Иконка в трее (UI-агент) показывает статус: адрес сервера, когда последний раз
удалось связаться, последняя ошибка. Кассиру там ничего менять не нужно.

### 5.3 Массовая раскатка

Скрипт раскатки и инсталлятор ещё не написаны (см. ограничения). Рабочий путь сейчас:
завести все ПК магазина списком → выгрузить архив конфигов → скопировать папку с
агентами и нужный `config.json` на каждую кассу (например, через `\\host\C$`) →
`--install` удалённо (`psexec`/WinRM) или руками.

## 6. Как проверить, что всё работает (демо за 5 минут)

1. Поднять сервер в Docker, залить `dev-seed.sql`, создать администратора.
2. На дашборде завести ПК с hostname тестовой машины, скопировать конфиг к агентам,
   запустить `AMadmin.ManagementAgent.exe --console` и `AMadmin.UiAgent.exe`.
3. Отправить оповещение «всем» — на тестовой машине появится окно.
4. На странице «Команды» отправить «Процесс → список» этому ПК — через минуту в
   «Результатах» будет список процессов кассы.

## 7. Известные ограничения (осознанный бэклог)

- Нет CSRF-защиты на POST-запросах панели и двухфакторной аутентификации.
- Инсталлятор клиента, самообновление агентов, скрипт массовой раскатки — не написаны.
- Просмотр серверного лога из панели — не сделан.
- Повторяющиеся оповещения и догон пропущенных — не реализованы.
- CRUD для магазинов и типов устройств, история по ПК, экспорт статистики, управление
  учётками администраторов из панели — нет отдельных экранов.
- SQLite не проверялась под нагрузкой 3000+ касс; при проблемах — отдельный трек.
- `.exe` не подписаны сертификатом — на масштабе SmartScreen/антивирусы будут мешать,
  подпись обязательна перед продом.

Актуальный чек-лист статуса — всегда в [README.md](README.md).
