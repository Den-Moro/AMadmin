Установка AMadmin

Развёртывание в один запуск: сервер — один скрипт, кассы — один скрипт на кассе или один скрипт на все кассы сразу с ПК администратора. Что здесь описано, проверено на Windows 11 (сервер в Docker) и на тестовой кассе. Эксплуатация после установки — в ADMIN.md.

Что нужно заранее

Где Что Зачем
Сервер Windows 10/11 или Linux с Docker (Docker Desktop / Docker Engine) всё остальное внутри образа
Сервер без Docker Windows + PowerShell; PHP поставится сам через winget пилот и до ~100 касс
ПК администратора PowerShell 5.1 (есть в Windows); для сборки клиента — .NET SDK 8 сборка и раскатка
Кассы Windows 7+, .NET Framework 4.8, доступ до сервера по сети (можно через прокси) агенты
Массовая раскатка админ-права на кассах, доступ к \\касса\C$ (SMB); WinRM — если включён, иначе schtasks copy + install

1. Сервер — один запуск

Вариант A: Docker (рекомендуется, годится для 3000 касс)

Windows (PowerShell, из папки репозитория):

.\deploy\server\install-server.ps1

Linux:

./deploy/server/install-server.sh

Скрипт соберёт образ (Apache + PHP 8.3, несколько рабочих процессов), поднимет контейнер на порту 8000 (-Port / первый аргумент), накатит миграции, при первом запуске спросит пароль для суперадмина admin и напечатает адрес панели и адрес для касс. База, файлы для раскатки, сессии и логи лежат на docker-томах и переживают обновление образа. Контейнер стартует сам после перезагрузки хоста.

Обновление сервера потом — тот же скрипт (или docker compose up -d --build).

Вариант B: без Docker, только Windows

.\deploy\server\install-server.ps1 -Mode Native

Из консоли администратора. Установит PHP 8.3 через winget (если нет), включит расширения и лимиты в php.ini, накатит миграции, создаст суперадмина, зарегистрирует сервер задачей планировщика «при загрузке» от SYSTEM и откроет порт в брандмауэре.

Встроенный веб-сервер PHP на Windows обрабатывает один запрос за раз. Для пилота и до ~100 касс этого достаточно; для полного парка используйте Docker или разверните PHP под IIS (FastCGI) / Apache — папка server/public — это DocumentRoot, все «несуществующие» пути должны уходить в public/index.php (.htaccess уже есть).

Сразу после установки

  1. Открыть http://<сервер>:8000/admin/login.html, войти как admin.
  2. Справочники → добавить магазины (типы устройств уже есть).
  3. Пользователи → завести коллег с нужными ролями; сменить свой пароль.
  4. Настройки → Сервер → уровень лога, окно «онлайн», защита входа.

2. Клиент — сборка комплекта (один раз на ПК администратора)

.\deploy\client\build-client.ps1

Получится dist\client\ (оба агента + установщик) и dist\AMadmin-client-<версия>.zip. Этот комплект одинаковый для всех касс — отличается только config.json.

3. Ключи касс — из панели

  • Одна касса: Дашборд → ＋ Добавить ПК → панель покажет config.json (кнопки «Скопировать» / «Скачать»).
  • Весь магазин: Дашборд → ＋ Добавить ПК → Списком → вставить hostname'ы → Выгрузить конфиги → архив с папкой на каждую кассу и config.json внутри.

Внутри — ключи доступа. Храните архив как пароли.

4. Установка на кассу

Одна касса, руками

Скопировать dist\client на кассу (например, в C:\AMadmin), положить рядом её config.json и запустить от администратора:

.\install-client.ps1

или без файла конфига:

.\install-client.ps1 -ServerUrl http://192.168.1.10:8000 -Token <ключ из панели>

Скрипт проверит .NET Framework 4.8, скопирует файлы в C:\AMadmin, поставит службу AMadminAgent (агент управления, от SYSTEM, автозапуск, авторестарт при сбое) и задачу планировщика «AMadmin UiAgent» (окно оповещений при входе любого пользователя, без прав администратора). Через минуту касса появится онлайн на дашборде.

Повторный запуск = обновление агента (конфиг сохраняется). Снять всё: .\uninstall-client.ps1 (-KeepConfig — оставить ключ).

Все кассы сразу, с ПК администратора

Распаковать архив конфигов (например, в C:\Temp\amadmin-configs) и:

.\deploy\client\deploy-clients.ps1 -ConfigsDir C:\Temp\amadmin-configs

Для каждой папки-hostname скрипт: проверит доступность, скопирует комплект и её config.json в \\HOST\C$\AMadmin, запустит там install-client.ps1 через WinRM (если включён) или разовой задачей планировщика от SYSTEM, и проверит, что служба появилась. В конце — таблица «касса → OK/ошибка». Параметры: -Hosts (подмножество), -Credential (если нужны отдельные админ-учётки), -Parallel (по умолчанию 8).

5. Проверка

  • Дашборд: касса онлайн, версия агента заполнена.
  • Оповещения → отправить тестовое «всем» → окно на кассе → в строке оповещения появилось подтверждение.
  • Команды → «Процесс → список» на эту кассу → через минуту результат в строке.

Если касса не появляется: C:\AMadmin\management-agent.log на кассе (доходит ли опрос: адрес сервера, прокси, TLS), затем лог сервера (docker compose logs или Настройки → Сервер → уровень debug).

6. Обновление

  • Сервер: git pull (или новая копия папки) → install-server.ps1 снова. Миграции накатываются сами, данные на месте.
  • Кассы: build-client.ps1 → deploy-clients.ps1 -ConfigsDir ... с тем же архивом конфигов (ключи не меняются) — агенты переустановятся поверх.
