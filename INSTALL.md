# Установка AMadmin

Развёртывание в один запуск: сервер — один скрипт, кассы — один скрипт на кассе или
один скрипт на все кассы сразу с ПК администратора. Что здесь описано, проверено на
Windows 11 (сервер в Docker) и на тестовой кассе. Эксплуатация после установки —
в [ADMIN.md](ADMIN.md).

## Что нужно заранее

| Где | Что | Зачем |
|---|---|---|
| Сервер | Windows 10/11 или Linux с **Docker** (Docker Desktop / Docker Engine) | всё остальное внутри образа |
| Сервер без Docker | Windows + PowerShell; PHP поставится сам через winget | пилот и до ~100 касс |
| ПК администратора | PowerShell 5.1 (есть в Windows); для сборки клиента — .NET SDK 8 | сборка и раскатка |
| Кассы | Windows 7+, **.NET Framework 4.8**, доступ до сервера по сети (можно через прокси) | агенты |
| Раскатка через GPO | домен, сетевая папка с доступом на чтение для компьютеров | стартовый скрипт |
| Раскатка с ПК администратора | админ-права на кассах, доступ к `\\касса\C$` (SMB); WinRM — если включён, иначе schtasks | copy + install |

## 0. Как запускать скрипты (важно)

Рядом с каждым `.ps1` лежит `.cmd` с тем же именем — **запускайте его** (двойным
кликом или из консоли: `install-server.cmd -Mode Native`). Он сам обходит политику
выполнения и переключает консоль в UTF-8.

Почему: архив с GitHub несёт на каждом файле пометку «скачано из интернета», и
PowerShell отказывает даже после `Set-ExecutionPolicy RemoteSigned` с ошибкой
*«is not digitally signed»*. Если всё же нужен прямой запуск `.ps1`:

```powershell
Get-ChildItem -Recurse -Filter *.ps1 | Unblock-File
powershell -ExecutionPolicy Bypass -File .\install-server.ps1 -Mode Native
```

(`-File` принимает только путь к файлу — параметры скрипта идут после него, не внутри кавычек.)

## 1. Сервер — один запуск

### Вариант A: Docker (рекомендуется, годится для 3000 касс)

Windows (из папки репозитория, двойной клик или консоль):

```
deploy\server\install-server.cmd
```

Linux:

```bash
./deploy/server/install-server.sh
```

Скрипт соберёт образ (Apache + PHP 8.3, несколько рабочих процессов), поднимет
контейнер на порту 8000 (`-Port` / первый аргумент), накатит миграции, при первом
запуске спросит пароль для суперадмина `admin` и напечатает адрес панели и адрес
для касс. База, файлы для раскатки, сессии и логи лежат на docker-томах и переживают
обновление образа. Контейнер стартует сам после перезагрузки хоста.

Обновление сервера потом — тот же скрипт (или `docker compose up -d --build`).

### Вариант B: без Docker, только Windows

```
deploy\server\install-server.cmd -Mode Native
```

Сам запросит права администратора (UAC). Установит PHP 8.3 через winget (если нет) и
найдёт его, даже если в этой консоли PATH ещё не обновился; включит расширения и
лимиты в `php.ini`, накатит миграции, создаст суперадмина, зарегистрирует сервер
задачей планировщика «при загрузке» от SYSTEM и откроет порт в брандмауэре.

> Встроенный веб-сервер PHP на Windows обрабатывает **один запрос за раз**. Для пилота и
> до ~100 касс этого достаточно; для полного парка используйте Docker или разверните
> PHP под IIS (FastCGI) / Apache — папка `server/public` — это DocumentRoot, все
> «несуществующие» пути должны уходить в `public/index.php` (`.htaccess` уже есть).

### Сразу после установки

1. Открыть `http://<сервер>:8000/admin/login.html`, войти как `admin`.
2. **Справочники** → добавить магазины (типы устройств уже есть).
3. **Пользователи** → завести коллег с нужными ролями; сменить свой пароль.
4. **Настройки → Сервер** → уровень лога, окно «онлайн», защита входа.

## 2. Клиент — сборка комплекта (один раз на ПК администратора)

```
deploy\client\build-client.cmd
```

Получится `dist\client\` (оба агента + установщики) и `dist\AMadmin-client-<версия>.zip`,
а рядом `dist\AMadmin-Startup.cmd` для GPO.
Этот комплект одинаковый для всех касс — отличается только `config.json`.

## 3. Ключи касс — из панели

- Одна касса: **Дашборд → ＋ Добавить ПК** → панель покажет `config.json`
  (кнопки «Скопировать» / «Скачать»).
- Весь магазин: **Дашборд → ＋ Добавить ПК → Списком** → вставить hostname'ы →
  **Выгрузить конфиги** → архив с папкой на каждую кассу и `config.json` внутри.

Внутри — ключи доступа. Храните архив как пароли.

## 4. Установка на кассу

### Одна касса, руками

Скопировать `dist\client` на кассу (например, в `C:\AMadmin`), положить рядом её
`config.json` и запустить от администратора:

```
install-client.cmd
```

или без файла конфига:

```
install-client.cmd -ServerUrl http://192.168.1.10:8000 -Token <ключ из панели>
```

Скрипт проверит .NET Framework 4.8, скопирует файлы в `C:\AMadmin`, поставит службу
`AMadminAgent` (агент управления, от SYSTEM, автозапуск, авторестарт при сбое) и
задачу планировщика «AMadmin UiAgent» (окно оповещений при входе любого пользователя,
без прав администратора). Через минуту касса появится онлайн на дашборде.

Повторный запуск = обновление агента (конфиг сохраняется). Снять всё:
`uninstall-client.cmd` (`-KeepConfig` — оставить ключ). Лог установки —
`C:\AMadmin\install.log`.

### Все кассы сразу через GPO (рекомендуется для домена)

Одна групповая политика — и каждая касса ставит и обновляет агентов при загрузке сама,
без WinRM и без обхода касс.

1. Сетевая папка с доступом на чтение для компьютеров домена (`Domain Computers`),
   например `\\SERVER\AMadmin`:
   - `client\` — содержимое `dist\client`;
   - `configs\` — распакованный архив «Выгрузить конфиги» из панели (папка на каждый
     hostname с `config.json` внутри);
   - `AMadmin-Startup.cmd` — из `dist\` (внутри поправьте `set SHARE=` на свой путь).
2. GPMC → политика на OU с кассами → *Computer Configuration → Policies → Windows
   Settings → Scripts (Startup/Shutdown) → Startup* → добавить
   `\\SERVER\AMadmin\AMadmin-Startup.cmd`.
3. При следующей загрузке касса найдёт свою папку в `configs\`, поставит агентов, службу
   и автозапуск окна. При каждой следующей загрузке — за секунду сверит версию и конфиг
   и ничего не тронет, если они не менялись. Кассы, которых ещё нет в `configs\`,
   пропускаются: заведите их в панели и обновите архив на шаре.
4. Обновление агентов: `build-client.cmd` → заменить `client\` на шаре → кассы обновятся
   при перезагрузке. Лог на кассе: `C:\AMadmin\install.log`.

Стартовый скрипт работает от SYSTEM, поэтому UAC не нужен; окно оповещений всё равно
запускается в сессии кассира — задачей планировщика при входе.

### Все кассы сразу с ПК администратора (без GPO)

Распаковать архив конфигов (например, в `C:\Temp\amadmin-configs`) и:

```
deploy\client\deploy-clients.cmd -ConfigsDir C:\Temp\amadmin-configs
```

Для каждой папки-hostname скрипт: проверит доступность, скопирует комплект и её
`config.json` в `\\HOST\C$\AMadmin`, запустит там `install-client.ps1` через WinRM
(если включён) или разовой задачей планировщика от SYSTEM, и проверит, что служба
появилась. В конце — таблица «касса → OK/ошибка». Параметры: `-Hosts` (подмножество),
`-Credential` (если нужны отдельные админ-учётки), `-Parallel` (по умолчанию 8).

## 5. Проверка

- Дашборд: касса **онлайн**, версия агента заполнена.
- Оповещения → отправить тестовое «всем» → окно на кассе → в строке оповещения
  появилось подтверждение.
- Команды → «Процесс → список» на эту кассу → через минуту результат в строке.

Если касса не появляется: `C:\AMadmin\management-agent.log` на кассе (доходит ли
опрос: адрес сервера, прокси, TLS), затем лог сервера
(`docker compose logs` или Настройки → Сервер → уровень `debug`).

## 6. Обновление

- **Сервер**: `git pull` (или новая копия папки) → `install-server.cmd` снова.
  Миграции накатываются сами, данные на месте.
- **Кассы**: `build-client.cmd` → через GPO — заменить `client\` на шаре; без GPO —
  `deploy-clients.cmd -ConfigsDir ...` с тем же архивом конфигов (ключи не меняются).
